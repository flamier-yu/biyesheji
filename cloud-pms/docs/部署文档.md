# 云协同 PMS 部署文档

本文档覆盖 **本地开发环境搭建**、**生产环境部署（Docker Compose）** 与 **常见问题排查**。

---

## 一、环境要求

| 组件 | 版本要求 | 说明 |
|---|---|---|
| JDK | 1.8 及以上 | 后端编译运行环境（推荐 1.8.0_461 或以上） |
| Maven | 3.6+ | 后端构建工具 |
| Node.js | 18+ | 前端构建（推荐 20 / 22 LTS） |
| MySQL | 8.0+ | 主数据库，需支持 `utf8mb4` |
| Redis | 3.0+ | 缓存与令牌存储（3.0 亦可用，客户端已使用 Jedis 兼容） |
| Nginx | 1.20+ | 生产环境反向代理（可选，本地开发不需要） |
| Docker | 20.10+ | 容器化部署（可选） |

**硬件建议**：开发机 8G 内存起步；生产单机部署建议 4 核 8G。

## 二、本地开发环境搭建

### 2.1 准备数据库

```bash
# 1. 创建数据库（注意字符集）
mysql -uroot -p -e "create database biyesheji default character set utf8mb4 collate utf8mb4_general_ci;"

# 2. 按顺序导入三个脚本（顺序不能颠倒）
mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/01-schema.sql
mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/02-data.sql
mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/03-business-menu.sql

# 3. 验证（应看到 23 张表）
mysql -uroot -p -e "use biyesheji; show tables;"
```

> ⚠️ **必须加 `--default-character-set=utf8mb4`**，否则中文数据会乱码。

#### 用图形客户端（Workbench / Navicat）导入时的问题

**症状**：

```
Error Code: 1175. You are using safe update mode and you tried to update
a table without a WHERE that uses a KEY column.
```

**原因**：`02-data.sql` 含大量 `DELETE FROM xxx;`（清空表后重新插入），
而 MySQL Workbench 默认开启「安全更新模式」（Safe Updates），
会拒绝执行不带 WHERE 或 WHERE 未使用索引列的 `UPDATE`/`DELETE`。

**本项目的处理**：`02-data.sql` 和 `03-business-menu.sql` 开头已内置

```sql
SET SQL_SAFE_UPDATES = 0;   -- 临时关闭（仅当前会话）
...
SET SQL_SAFE_UPDATES = 1;   -- 执行完恢复
```

所以**直接在 Workbench 里执行即可，无需改任何设置**。

若仍报同样的错，按以下顺序排查：

| 排查项 | 做法 |
|---|---|
| 客户端未重连 | 脚本里的 `SET` 只对当前连接生效。执行前先重新连接一次数据库 |
| 只选中了部分语句执行 | Workbench 里用「执行整个脚本」(闪电图标带光标) 而不是「执行当前语句」，否则会漏掉开头的 `SET` |
| 客户端版本差异 | 备选方案：执行前手动加一行 `SET SQL_SAFE_UPDATES = 0;` |
| 不想动 SQL | 关掉客户端限制：Workbench → Edit → Preferences → SQL Editor → 取消 *Safe Updates* → **重连数据库生效** |

> 最省事的替代方式：用命令行执行，命令行默认不受 Safe Updates 限制：
> ```bash
> mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/02-data.sql
> ```

编辑 `pms-server/src/main/resources/application-dev.yml`：

```yaml

    url: jdbc:mysql://127.0.0.1:3306/biyesheji?...
```

### 2.4 启动后端

```bash
cd pms-server
mvn clean package -DskipTests

# 启动（注意：必须显式指定端口）
java -jar target/pms-server.jar --server.port=8080
```

**⚠️ 为什么必须写 `--server.port=8080`？**
某些 CI/沙箱环境会注入 `SERVER_PORT` 环境变量，若不显式指定，应用可能绑定到意料之外的端口（甚至因端口被占用而启动失败）。显式指定命令行参数优先级最高，可避免这类问题。

启动成功标志：

```

云协同 PMS 启动成功！
本地地址：http://localhost:8080/
接口文档：http://localhost:8080/doc.html
```

### 2.5 启动前端

```bash
cd pms-web
npm install
npm run dev
```

访问 http://localhost:5173 ，默认账号 **admin / admin123**。

## 三、Docker 部署完整流程（定稿版）

### 3.0 流程总览

一句话：**开发机构建 → 上传 4 项产物 → 服务器一条命令启动**。

```
┌─────────── 开发机 ───────────┐          ┌────────── 服务器 ──────────┐
│ mvn package       → jar      │          │ /opt/pms/                  │
│ npm run build     → dist     │  scp 上传 │  ├── pms-server.jar        │
│ 把 4 项产物放到     │          │  ├── dist/                 │
│ deploy-out/        │ ────────→ │  ├── docker-compose.yml    │
│  ├── pms-server.jar 75.1 MB │          │  └── nginx.conf            │
│  ├── dist/          2.7 MB  │          │                            │
│  ├── docker-compose.yml     │          │ docker compose up -d       │
│  └── nginx.conf     2.5 KB  │          │   （无需 --build）          │
└──────────────────────────────┘          └────────────────────────────┘
```

| 角色 | 需要安装 | 职责 |
|---|---|---|
| **开发机** | JDK 8 + Maven + Node 18+ | 只负责构建产物 |
| **服务器** | **仅 Docker 20.10+**（含 compose 插件） | 运行三个容器 |
| **MySQL** | 任意位置（本机/独立服务器/云 RDS） | 数据库，独立于编排 |

> 服务器上**没有**源码、没有 JDK/Maven/Node、没有 Dockerfile、没有 SQL 脚本 —— 只有 4 项产物。

### 3.1 第一步：准备数据库（一次性，在 MySQL 所在机器执行）

**① 建库并导入数据**

```bash
mysql -uroot -p -e "create database biyesheji default character set utf8mb4 collate utf8mb4_general_ci;"
mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/01-schema.sql
mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/02-data.sql
mysql -uroot -p --default-character-set=utf8mb4 biyesheji < sql/03-business-menu.sql
```

> MySQL Workbench / Navicat 导入若报 `Error Code: 1175`，见第二章 2.1 节说明（脚本已内置处理，重连后执行即可）。

**② 给应用账号授权远程访问**

```bash
mysql -uroot -p < deploy/init-external-db.sql
```

该脚本会创建专用账号 `pms`（而不是直接用 root）并只授予 `biyesheji` 库的权限。

**③ 检查两处系统配置（最容易漏）**

| 检查项 | 说明 |
|---|---|
| `bind-address` | 若为 `127.0.0.1`，外部连不上。执行 `SHOW VARIABLES LIKE 'bind_address';` 确认，需改为 `0.0.0.0` |
| 防火墙 / 安全组 | MySQL 与 Docker 不同机时需放行 3306 端口 |

```sql
-- 验证授权结果
SELECT User, Host FROM mysql.user WHERE User = 'pms';
SHOW GRANTS FOR 'pms'@'%';
```

### 3.2 第二步：本地构建产物（在开发机执行）

构建完成后，把两项产物拷贝到 `deploy-out/` 目录（要与 `docker-compose.yml` 同结构放置）：

```bash
# 构建后端
cd pms-server && mvn package -DskipTests && cd ..
# 产物：pms-server/target/pms-server.jar

# 构建前端
cd pms-web && npm install && npm run build && cd ..
# 产物：pms-web/dist/
```

产物放置位置（**文件名必须一致，compose 按此名挂载**）：

| deploy-out/ 里的文件 | 来自 | 大小 |
|---|---|---|
| `pms-server.jar` | `pms-server/target/*.jar`（拷贝后重命名） | ~75 MB |
| `dist/` | `pms-web/dist/` 整个目录 | ~2.7 MB |
| `docker-compose.yml` | 项目根目录 | 3 KB |
| `nginx.conf` | `deploy/nginx.conf` | 2.5 KB |

### 3.3 第三步：上传产物（在开发机执行）

```bash
scp -r deploy-out/* user@服务器IP:/opt/pms/
```

上传后服务器上的目录结构（**就这 4 项**）：

```
/opt/pms/
├── pms-server.jar       ← 后端产物
├── dist/                ← 前端产物
├── docker-compose.yml   ← 编排文件
└── nginx.conf           ← Nginx 配置（必须单独传，compose 无法内联文件内容）
```

> `sql/` 和 `deploy/init-external-db.sql` 属于一次性数据库初始化动作（3.1 节），
> **不需要上传到应用服务器**。

### 3.4 第四步：启动（在服务器执行）

```bash
cd /opt/pms
docker compose up -d          # 注意：没有 --build，官方 JRE 镜像直接挂载 jar
docker compose ps             # 三个容器应为 Up / healthy
docker compose logs -f backend
```

启动成功标志：

```
Tomcat started on port(s): 8080 (http)
云协同 PMS 启动成功！
```

访问 `http://<服务器IP>`（默认 80 端口），默认账号 `admin / admin123`。

**关于数据库配置（.env 完全可选）**：

数据库连接的默认值已内嵌在 compose 里（`${DB_HOST:-host.docker.internal}` 等），
**默认配置可直接启动，无需任何配置文件**。仅当实际情况与默认值不同时，
在 `/opt/pms/` 下创建 `.env` 覆盖：

| 变量 | 默认值 | 何时需要改 |
|---|---|---|
| `DB_HOST` | `host.docker.internal` | MySQL 不在本机时改为对方 IP；同机时**必须用它**（容器内的 127.0.0.1 指容器自己） |
| `DB_PORT` | `3306` | MySQL 端口非默认时 |
| `DB_NAME` | `biyesheji` | 库名不同时 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `root` | **生产必改**（建议用 `pms` 专用账号） |
| `JWT_SECRET` | 开发默认值 | **生产必改**，`openssl rand -base64 48` 生成 |
| `BACKEND_PORT` / `WEB_PORT` | `8080` / `80` | 端口冲突时 |

### 3.5 第五步：验证

| 检查项 | 方式 | 期望 |
|---|---|---|
| 容器状态 | `docker compose ps` | 3 个容器 Up，redis 为 healthy |
| 后端健康 | `curl http://localhost:8080/actuator/health` | `UP` 且 db / redis 均 UP |
| 前端页面 | 浏览器访问 `http://服务器IP` | 登录页正常显示 |
| 登录链路 | admin / admin123 登录 | 进入工作台 |
| 实时推送 | 消息中心页显示"实时推送 已连接" | WebSocket 通 |

### 3.6 日常更新（版本升级流程）

**只更新后端**：

```bash
# 开发机：重新打包，替换服务器上的 jar
cd pms-server && mvn package -DskipTests
scp target/pms-server.jar user@服务器IP:/opt/pms/

# 服务器
cd /opt/pms && docker compose restart backend
```

**只更新前端**（连重启都不用 —— dist 是挂载的，替换即时生效）：

```bash
# 开发机：重新构建，替换服务器上的 dist
cd pms-web && npm run build
scp -r dist/* user@服务器IP:/opt/pms/dist/

# 服务器：无需任何操作
```

**同时更新**：替换两个产物后 `docker compose restart backend` 即可，frontend 容器无需重启。

### 3.7 连通性排查

混合部署最常见的卡点是「容器连不上宿主机数据库」，按顺序排查：

```bash
# ① 容器内能否解析宿主主机名
docker compose exec backend ping -c 2 host.docker.internal

# ② 容器内能否连通 3306 端口
docker compose exec backend sh -c "nc -zv host.docker.internal 3306 || telnet host.docker.internal 3306"

# ③ 用应用账号从容器内直连测试（排除口令与授权问题）
docker compose exec backend sh -c "mysql -h host.docker.internal -u pms -p'Pms@2026' -e 'SELECT 1;'"

# ④ 查看后端启动日志中的具体报错
docker compose logs backend | grep -i -E "error|exception|denied|refused"
```

| 报错关键字 | 含义 | 解决 |
|---|---|---|
| `Connection refused` | 端口不通 | 检查 MySQL 是否启动、bind-address、防火墙 |
| `Access denied for user` | 账号或密码不对 | 核对 `.env`；确认授权脚本已执行 |
| `Unknown database` | 库不存在 | 执行建库语句 |
| `Communications link failure` | 网络层不通 | 检查 `DB_HOST` 填写是否正确（同机是否写成 127.0.0.1） |
| `Public Key Retrieval is not allowed` | MySQL 8 认证插件问题 | 确认 JDBC URL 带了 `allowPublicKeyRetrieval=true`（compose 已包含） |

### 3.8 非 Docker 部署（完全不用容器）

若目标机器没有 Docker，可全手工部署：

**后端**（Linux）：

```bash
nohup java -Xms256m -Xmx512m -DLOG_HOME=/opt/pms/logs \
  -jar /opt/pms/pms-server.jar --server.port=8080 \
  > /opt/pms/logs/startup.log 2>&1 &
```

**前端 + Nginx**：

```bash
# 将 dist 放到 Nginx 站点目录
cp -r dist/* /usr/share/nginx/html/

# 使用项目提供的配置
cp nginx.conf /etc/nginx/conf.d/pms.conf
nginx -t && nginx -s reload
```

### 3.9 关键配置项（生产必改）

| 配置 | 位置 | 说明 |
|---|---|---|
| `JWT_SECRET` | 服务器 `.env` | **必须修改**，`openssl rand -base64 48` 生成，compose 已预留变量 |
| `DB_USERNAME` / `DB_PASSWORD` | 服务器 `.env` | **不要用 root/root**，建议用 `deploy/init-external-db.sql` 创建的 `pms` 账号 |
| 验证码开关 | `pms.captcha-enabled`（jar 内配置） | 生产建议保持 `true` |
| 上传大小上限 | `spring.servlet.multipart.max-file-size` | 默认 50MB |
| `LOG_HOME` | compose command 已指向 `/app/logs`（挂载到服务器 `./logs`） | 日志按天滚动保留 30 天 |

> 改 `.env` 后执行 `docker compose up -d` 即可让新配置生效（compose 会重建受影响的容器）。

## 四、常见问题排查

### 4.1 启动失败类

| 现象 | 原因 | 解决 |
|---|---|---|
| `Port 8080 was already in use` | 端口被占用 | 换端口 `--server.port=8081`，或查杀占用进程 |
| 端口跑到意料之外的端口 | 环境注入了 `SERVER_PORT` | 显式加 `--server.port=8080` |
| `Access denied for user` | 数据库账号密码不对 | 检查 `application-dev.yml` |
| `Unknown database 'biyesheji'` | 没建库 | 执行建库语句 |
| 启动卡在 HikariPool | 数据库连不上 | 检查网络、防火墙、账号权限 |
| `Communications link failure` | MySQL 未启动或时区配置问题 | 确认服务在跑，URL 加 `serverTimezone=Asia/Shanghai` |

### 4.2 功能异常类

| 现象 | 原因 | 解决 |
|---|---|---|
| 中文乱码 | 导入 SQL 未指定字符集 | 加 `--default-character-set=utf8mb4` 重新导入 |
| **Error Code: 1175** 安全更新模式 | 客户端（Workbench 等）拦截无 WHERE 的 DELETE | 脚本已内置开关；若仍报错，看 2.1 节的排查表 |
| 登录一直提示「账号或密码错误」 | ① 密码不对 ② 数据库里密码字段为空 ③ 表里有非表字段未标注 | 用 `PasswordGenerator` 重新生成密文；检查实体是否有 `@TableField(exist = false)` 遗漏 |
| 登录提示验证码错误 | 验证码已过期（2 分钟） | 刷新验证码；或临时关闭 `pms.captcha-enabled` |
| 接口返回 401 | 令牌过期或未携带 | 重新登录；检查请求头 `Authorization: Bearer <token>` |
| 接口返回 403 | 当前角色无该权限 | 到「角色管理」为角色勾选对应菜单权限 |
| 页面菜单不显示 | 角色未授权该菜单 | 角色管理中重新分配；或该目录下没有子菜单（前端会过滤空目录） |
| 访问根路径跳到 404 | 动态路由未补根路径规则 | 确认 `router/index.js` 中有 `path: '/'` 的重定向 |
| 侧边栏/顶栏显示两遍 | 路由 Layout 嵌套 | 检查 `buildRoutes` 是否只对顶层菜单包 Layout |

### 4.3 前端类

| 现象 | 原因 | 解决 |
|---|---|---|
| 端口从 5173 变成 5174 | 有僵尸 vite 进程占着 5173 | 清理残留 node 进程后重启 |
| 请求 404 / 跨域 | 代理未生效或后端未启动 | 检查 `vite.config.js` 的 `/dev-api` 代理与后端状态 |
| 页面空白 | 动态路由未注册成功 | 看浏览器控制台，检查 `/getRouters` 是否返回 200 |
| npm install 极慢 | 未配置国内镜像 | `npm config set registry https://registry.npmmirror.com` |

### 4.4 Maven 类

| 现象 | 原因 | 解决 |
|---|---|---|
| 依赖下载极慢/卡住 | 走默认中央仓库 | 在 `~/.m2/settings.xml` 配置阿里云镜像 |
| `mysql-connector-java version is missing` | Spring Boot 2.7.18 已改用新坐标 | 用 `com.mysql:mysql-connector-j` |
| 编译报「找不到符号」 | 依赖未引入完全 | 核对 `pom.xml`，尤其 `spring-boot-starter-websocket` |
