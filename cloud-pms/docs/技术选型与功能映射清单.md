# 毕业设计项目方案：云协同 PMS 企业项目管理系统

> 技术选型 · 功能-技术映射 · 论文挂钩 · 依赖模板
> 适用范围：Spring Boot + Vue 技术栈的本科毕业设计

---

## 一、选题定位

### 1.1 推荐选题

**云协同 PMS —— 中小企业项目全生命周期管理系统**

备选名称：星火项目管理平台 / 智汇项目协同系统 / 弈项目管理系统

### 1.2 为什么选这个场景

| 优势 | 说明 |
|---|---|
| 角色天然分层 | 系统管理员 / 项目经理 / 项目成员 / 访客，RBAC 权限模型有充足内容可写 |
| 业务链路完整 | 立项 → 计划 → 任务 → 执行 → 验收 → 结项，每个环节都能挂技术点 |
| 技术点不硬塞 | 定时任务、消息通知、文件存储、统计报表都由业务自然派生 |
| 可视化需求强 | 甘特图、燃尽图、工时统计、数据大屏，ECharts 有充足发挥空间 |
| 数据规模可控 | 15~18 张表，够写数据库设计章节，又不会失控 |
| 答辩好演示 | 界面美观、流程可走通、图表直观，演示环节容易拿到印象分 |

### 1.3 系统角色定义

| 角色 | 核心权限 |
|---|---|
| 系统管理员 | 用户/角色/菜单/字典/日志/参数配置全量权限 |
| 项目经理 | 立项申请、任务分配、工时审批、项目报表、结项 |
| 项目成员 | 查看参与项目、领取/完成任务、填报工时、上传文档 |
| 访客 | 只读查看公开项目进度 |

## 十、答辩常见问题与话术

| 老师可能问 | 回答要点 |
|---|---|
| 为什么用 Spring Boot 而不是 SSM？ | 自动配置减少 XML 配置量、起步依赖统一版本管理、内嵌容器便于部署；SSM 需要大量手工配置 |
| 一个小系统为什么用 MQ？ | 站内信与邮件通知异步化，发通知不阻塞任务指派主流程，同时具备错峰削峰能力；也便于后续扩展短信、企业微信等多渠道 |
| 为什么用 Redis 不用本地缓存？ | 需要多实例共享登录态与 Token；验证码、排行榜（ZSet）等场景本地缓存无法满足 |
| 为什么用 Elasticsearch？ | 项目文档达到万级后 LIKE 模糊查询无法利用索引，ES 倒排索引可支撑全文检索与高亮 |
| JWT 和 Session 的区别？ | JWT 无状态、可跨服务、适合前后端分离；Session 需要服务端存储、分布式场景需共享 |
| 密码为什么用 BCrypt？ | 自带随机盐、计算成本可调，抗彩虹表与暴力破解；MD5 已被证明不安全 |
| 数据权限怎么实现的？ | 自定义 MyBatis-Plus 拦截器，根据当前用户角色拼接部门/本人条件到 SQL |
| 并发下任务状态会不会错乱？ | 状态流转用乐观锁（version 字段），更新时校验版本号，冲突则提示刷新 |
| 大文件上传怎么处理的？ | 前端按固定大小切片，逐片上传并记录已传分片到 Redis，全部完成后服务端合并；支持断点续传与 MD5 秒传 |
| 系统测试怎么做的？ | 功能测试设计等价类与边界值用例；接口测试用 Postman；性能测试用 JMeter 模拟并发登录与查询 |
